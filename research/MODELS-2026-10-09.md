### a) Runtime support for DeepseekV41ForCausalLM
- **vLLM: yes, upstream.** "[Model] Support DeepSeek-V4.1-Flash (#56214)", commit e77daef89; image `vllm/vllm-openai:deepseekv41-flash-0909`. Tracking issue still open: https://github.com/vllm-project/vllm/issues/57448 . NVIDIA card: `vllm serve ... --tensor-parallel-size 4` https://huggingface.co/nvidia/DeepSeek-V4.1-Flash-NVFP4
- **vLLM on GB10/sm_121: stock does NOT serve.** Issue #56461 (open): fails in `flashinfer_sparse_mla_warmup` — SWA cache block 32 vs SM120 decode page 64, ratio-1 indexer block_kv=128 vs DeepGEMM sm120 (64 only); reproduced on aarch64 GB10. https://github.com/vllm-project/vllm/issues/56461 . Draft fix PR #57292 (same thread); a third FlashInfer gap (`extra_page_block_size==32`, flashinfer#5174) is noted by commenters on SM120. Community forks fix it (below).
- **vLLM TP4 on 4 Sparks: works in a fork.** tonyd2wild/DeepSeek-V4.1-Flash-vLLM-DGX-Spark: patched vLLM commit `e47aa780b`, sm121 extension build, Engram-on-disk patch, DSpark, CUDA graphs. https://github.com/tonyd2wild/DeepSeek-V4.1-Flash-vLLM-DGX-Spark . It warns that later vLLM heads emit one repeated garbage token with those patches, so build from the pinned commit.
- **vLLM 2-Spark (0xSero):** uses `ghcr.io/0xsero/deepseek-v4.1-flash-spark` (vLLM r38 + EXL3 MoE + B12X, `--attention-backend B12X --linear-backend b12x --moe-backend b12x`). https://huggingface.co/0xSero/DeepSeek-V4.1-Flash-Spark . Whether the eugr/spark-vllm-b12x image carries dsv41 support: **unverified**.
- **SGLang: yes, on GB10 TP4.** Upstream `dsv4.1` branch; NVIDIA tested `lmsysorg/sglang:dev-cu13-dsv41` (GB300). SGLang roadmap https://github.com/sgl-project/sglang/issues/42170 . MiaAI-Lab runs it on GB10 sm_121, TP3 and TP4 (below).
- **TensorFold/EXL3: yes, TP2 only.** bertholomus engine (Zig, aarch64, `-Dsm=121`), `TF_TP_WORLD=2`; no 4-rank mode documented. https://huggingface.co/bertholomus/DeepSeek-V4.1-Flash-TensorFold-TP2-2xGB10
- **llama.cpp/GGUF: not merged.** Only open PR "model : add DeepSeek V4.1 (DeepseekV41ForCausalLM)" https://github.com/ggml-org/llama.cpp/pull/28696 ; no V4.1 GGUF found.
- DeepSeek's own `inference/` is a reference torchrun implementation (convert.py to per-rank TP files, `torchrun --nproc-per-node MP generate.py`), "not a production serving engine". https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/main/inference/README.md

### b) Engram offload and resident memory
- Engram = layers 1 and 14, tables of 384,006,168 and 384,016,682 rows, ~98 GB each at FP8 (config.json https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/main/config.json ; 0xSero card "2 x 98.3 GB").
- **Upstream vLLM:** `--engram-config '{"cpu_offload": true}'` puts tables in pinned host RAM: 23.60 GiB per rank per Engram layer, weights 79.1 GiB per rank at TP4 (measured on 4x RTX PRO 6000) — https://github.com/vllm-project/vllm/issues/56461 (comment by munakaya). On a Spark host RAM *is* the GPU pool: 79.1 + 47.2 = ~126 GiB > ~121 GiB usable, so this does not fit. tonyd2wild states the same ("vLLM keeps them in host memory, and on a DGX Spark host memory is the GPU pool").
- **Disk offload:** 0xSero's vLLM fork: `--engram-config '{"table_memory":"disk","cpu_offload":false}'` (https://huggingface.co/0xSero/DeepSeek-V4.1-Flash-Spark). tonyd2wild: own Engram-on-disk patch, rows staged before the forward, node-local sparse copy of each rank's rows (48 GB on disk per worker). MiaAI-Lab SGLang: NVMe-resident tables (`OFFLOAD_MODE=ram` explicitly forbidden on Sparks), `DSV41_CACHE_GIB=4` row cache with 67-76% hit rate. https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-DGX-Sparks , https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-DGX-Sparks/blob/main/docs/tp4.md
- **Resident per node at TP4, FP8 (original) checkpoint:** with Engram on disk, ~77 GiB (MiaAI-Lab: "~77 GiB of weights per rank instead of ~101" at TP3) to 81.58 GiB (tonyd2wild boot 10, includes DSpark draft layers + vision encoder). https://github.com/tonyd2wild/DeepSeek-V4.1-Flash-vLLM-DGX-Spark . With Engram in host RAM: ~79 + 47 = ~126 GiB (does not fit).
- **NVFP4 checkpoint:** no GB10 measurement exists. My estimate (not a source): experts were already 4-bit, NVFP4 only adds scale overhead (card: 476 -> 492 GiB total), so ~+3-4% over the original, i.e. ~80-85 GiB/rank with Engram on disk. No saving versus the original.

### e) Verdict
**Most viable: SGLang TP4 (EP1) from MiaAI-Lab's `start-tp4.sh` (ring block, `NCCL_SWITCHLESS_RING_ONLY=1`, RoCEnante, patched NCCL) on the ORIGINAL `deepseek-ai/DeepSeek-V4.1-Flash` (510.3 GB), Engram on NVMe.** It is the only recipe that matches our topology (4-node ring), has ring-specific measured numbers (60-120 tok/s c1, 345-520 agg at c8-16) and needs no quantisation loss. Runner-up: tonyd2wild vLLM TP4 (closer to the eugr/vLLM stack but slower, 74-95 tok/s c1 code, fork pinned to an old commit). TensorFold is faster per stream (~90-100 tok/s) but TP2 only, so it leaves two Sparks idle.
Which checkpoint: **deepseek-ai/DeepSeek-V4.1-Flash**. The NVIDIA NVFP4 is larger (527 GB), was validated only on GB300, gains nothing on weights that were already 4-bit, and its NVFP4 MoE backend (`flashinfer_trtllm_routed`) is untested on sm_121. Do not use the 0xSero/Mia EXL3 files for TP4 vLLM/SGLang unless you want the 3.5 bpw TP4 lane (more KV, lower quality).
Disk: 510 GB per node fits the 916 GB NVMe, plus ~48 GB node-local Engram rows per worker; MiaAI-Lab can NFS-share from sparkmain (3.7 TB).
Expected blockers (ours):
1. Patched NCCL for the ring (sparkring, external prerequisite, must build aarch64 sm_121). Prefill ~30% lower than switched.
2. spark4 runs a different kernel/driver (7.0.0 / 580.178.04 vs 6.17 / 580.173.02): suspect first if it will not join. The fork authors' fleets are homogeneous, so this is untested.
3. Memory headroom: ~77-82 GiB weights + KV + graphs on a 121 GiB pool; MiaAI-Lab reports only ~6 GB left on the head and a JIT wedge that reset all four nodes in tonyd2wild's boot 3 (prebuild kernels, `MAX_JOBS=2`).
4. GB10 "slow state" (tonyd2wild issue #1): 70 vs 230 GB/s GEMV flips, up to 1.5x on a cell; and clock latch on 2 of their 4 Sparks.
5. Upstream vLLM does not serve dsv41 on sm_121 yet (#56461); everything works only through forks/patch overlays, so expect to pin commits (images are in each repo).
6. Our NCCL HCA pinning decision (dual-rail: all four devices) is still open; MiaAI-Lab pins `B12X_ROCE_HCA=rocep1s0f0,roceP2p1s0f0`, and says devices past the second are never advertised by default (see the "Devices past the second" section of switchless-ring.md).
7. EP>1 all-to-all needs routes between non-adjacent ranks; use EP_SIZE=1 as in the production line (our earlier finding: RoCE cannot cross the ring for non-neighbours).

### Ranked shortlist
1. **drowzeys/keys-GLM-5.3-EXL3-2.75BPW (276 GB)** — full 753B GLM-5.3, only entry with measured 4-Spark TP4 numbers (~40 tok/s single stream, 1M ctx); TensorFold engine, same family as our glm53-flash-tf job; 2.75 bpw quality loss.
2. **nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-NVFP4 (352 GB)** — official NVFP4, vLLM/SGLang, TP4-divisible, 1M ctx; but 55B active (bandwidth-heavy on 273 GB/s nodes) and no GB10 evidence — a research bet.
3. **Qwen/Qwen3.5-397B-A17B-FP8 (406 GB)** — mainstream vLLM/SGLang support, 17B active so fast, FP8 quality; only 2-Spark INT4 evidence on GB10, tight KV room (~78 GB free).
4. **doth4580/MiMo-V2.6-Pro-RL-EXL3-3.05bpw-hq (393 GB)** — newest (Sep-Oct 2026) 1T-class model; Spark runtime unverified, other recipes need 8 Sparks.
5. **bullerwins/DeepSeek-V4-Pro-0813-exl3-2.04bpw (435 GB)** — only way to touch V4-Pro; ~2 bpw and no Spark-only engine published (DS4RT needs an RTX PRO 6000).
Not worth it: GLM-5.3 NVFP4 (465 GB, no KV room), Kimi-K3 (1.5 TB; 1-bit pruned only).
