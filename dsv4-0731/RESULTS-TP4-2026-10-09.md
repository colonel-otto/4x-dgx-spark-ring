**Deviation: `--load-format safetensors` instead of `instanttensor`.** InstantTensor takes torch's raw `ncclComm` and drives it with its
own NCCL calls. Under the switchless NCCL it broke twice:
- boot 1: `instanttensor._C.open` → `RuntimeError: std::exception`, then `NCCL WARN Error: corrupted comm object detected`. Two NCCLs
  were mapped: the preload `/opt/patched-nccl/libnccl.so.2.30.7` and the image's system `/usr/lib/aarch64-linux-gnu/libnccl.so.2.31.2`.
- boot 3, after shadowing both system/pip copies with the patched lib: `!!!!!!! Segfault encountered !!!!!!!` on rank 0 at InstantTensor's first all-gather.
- boot 2 never started: Docker 29.6 on spark4 refuses `docker cp` (mod install) into a container with a `:ro` *file* bind
  (`openat usr/lib/aarch64-linux-gnu/libnccl.so.2.31.2: read-only file system`). Fix: rw binds of a copy (`/opt/nccl-shadow`).
The shadow binds are kept (only one NCCL per process). This deviation changes the load path only; it does not change steady-state serving.

**Cold start: 670 s** to `Application startup complete` (launcher start to API ready). That includes weights 74 s + draft 16 s
(model load 41.29 GiB/rank, 104.5 s) and init engine 165.8 s (compile 15.0 s, graph capture 21 s), plus container/mod setup. The JIT caches were cold on spark4.
TP=3 reference: ~4.3 min with warm caches, ~8 min cold, using instanttensor.

**KV pool: 5,408,951 tokens** (52.83 GiB available for KV per rank, max_model_len auto = 1,048,576, 5.16x concurrency at 1M).
TP=3 had 2,364,598 tokens (2.29x) and TP=2 had 13,107 tokens (max len 11,948).

**Memory per node** (`free`, `logs/memmon-*.tsv`, 15 s sampling): steady state used 109-111 G, available 9-12 G, GPU process 100.97 GB on every rank.
Minimum available during load was 11.6-13.9 G and during the benchmark 9.5-11.9 G (sparkmain lowest). Swap rose during load and then held:
sparkmain 1.6→3.9 G, spark1 0.4→2.2 G, spark2 0.5→2.3 G, spark4 0→3.0 G. No OOM. Temperatures reached 78-81 °C during the benchmark (no cooldown gate between cells).
