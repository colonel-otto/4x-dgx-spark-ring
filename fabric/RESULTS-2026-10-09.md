## 3. Dual-rail per edge and full ring (ib_write_bw -D 10 --report_gbits, one process per link, all clients started together)
| test | result (Gb/s per link) |
|---|---|

| edge 3 both rails | 98.01 + 98.01 = 196.0 |
| edge 4 both rails | 98.01 + 98.01 = 196.0 |
| ALL 8 links at once, unidirectional (each node sends on 2 ports, receives on 2) | every link 98.01 - 98.02, total 784 Gb/s |
| edge 1 both rails, `-b` bidirectional | 195.72 + 195.72 (value is send+receive sum per link, i.e. ~98 per direction per rail) |
| ALL 8 links at once, `-b` bidirectional | 95.75 - 96.76 per link (send+receive sum), i.e. 770 Gb/s total, ~48 per direction per link |

Reading: two rails on one node cap at 196 Gb/s per direction (98 each, vs 109 alone), which matches the previous figure. Running all 8 links at once
does not lower it further in the unidirectional case (each node already carries 2 tx + 2 rx = 196 tx / 196 rx). In the bidirectional full-ring case
each node moves 4 links x ~96 = ~385 Gb/s send+receive combined = ~193 per direction, only ~2% under the unidirectional ceiling. So there is a
node-level ceiling of ~196 Gb/s per direction (about 98 per port when 2 ports transmit), not a per-cable one, and the ring itself adds no extra loss
(slight 98.0 -> 95.8 slope from E1 to E4 under bidir full load).

## 7. Anomalies
A1. **NCCL cannot run np=3 or np=4 on this fabric (stock NCCL 2.30.7).** Every op, both rail modes:
 `NCCL WARN Call to ibv_modify_qp failed with 110 Connection timed out, on dev rocep1s0f0:1, curr state INIT, next state RTR, local GID index 3, local GID ::ffff:10.100.164.2, remote GID ::ffff:10.100.166.1`
 (np=3, sparkmain trying to reach spark2; np=4 first warning came from `gx10-3c91 ... local GID ::ffff:10.100.162.1, remote GID ::ffff:10.100.166.1`), preceded by 34 retries; mpirun exit=3.
 Cause: NCCL pairs the same-index HCA on both ends of every connection, but every cable is f0<->f1, and NCCL also builds trees / connections between non-adjacent ranks
 (e.g. `2[0] -> 0[0]` with NCCL_CROSS_NIC=1 probe, logs/probe.*). With a rank-independent HCA list this holds even at np=2 (A2). With a fabric-only NCCL_SOCKET_IFNAME the run does not
 even bootstrap: `ncclOsSocketPollConnect: connect to 10.100.164.2<53079> returned Connection timed out, retrying (1/34)` (spark2 cannot reach sparkmain on a fabric address; run hung, killed by timeout, exit=124; logs/nccl.all_reduce.np3.rail1.fabric.log, np4 likewise).
 Any 3 of 4 nodes in a 4-ring is a chain with a missing edge. The upstream recipe uses a custom `switchless-nccl v0.0.1` build; it is not present on this host and was not tried.
 I did not try NCCL_ALGO=Ring/per-rank asymmetric lists beyond the probes (MERGE_NICS 0/1, CROSS_NIC=1 all fail identically): a ring needs send on f0 and receive on f1 per rank, which stock NCCL did not do.
A2. **The cluster-notes HCA recommendation (same list on all ranks, `rocep1s0f0,rocep1s0f1`) fails even at np=2**: `Call to ibv_modify_qp failed with 110 Connection timed out ... local GID ::ffff:10.100.164.2, remote GID ::ffff:10.100.160.2`
 (sparkmain f0 -> spark1 f0, which is cabled to spark2) (`logs/nccl-failure.merged-nics.np2.rail1.log`, `...unmerged-nics...`; also with NCCL_IB_MERGE_NICS=0). np=2 works only with per-rank crossed lists (sparkmain f0, spark1 f1).
A3. NCCL_SOCKET_IFNAME could not be a single fabric netdev for np>=3 (bootstrap needs non-adjacent ranks to reach rank 0) so the LAN `enP7s7` was used for bootstrap in the failing np>=3 runs.
 np=2 runs bootstrap over the fabric (sparkmain enp1s0f0np0, spark1 enp1s0f1np1); launch/OOB is on the LAN in all runs.
A4. Rail 2 latency tail is heavier than rail 1 on all four edges (see section 1), median unchanged.
A5. Non-adjacent ICMP unreachable, stray route on spark1 (section 4).
A6. nvidia-smi on sparkmain: `18.79 W`, memory N/A (stale util counter as noted in cluster notes); GPUs were idle. Containers open-webui, node-exporter, dcgm-exporter were running before and were left alone.
A7. Image IDs of `ntests:2.30.7` differ per node; spark4 has the sparkmain copy. spark4 also now has `~/nccl-tests/build` (host build, unusable there) and `~/bench/fabric-2026-10-09/ntbuild`; spark1/spark2 have the ntbuild copy.
